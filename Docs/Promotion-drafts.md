# Manage-A 홍보 준비

조회·작성: 2026-10-28. 외부 커뮤니티에 게시하거나 메시지를 보내지 않은 초안이다. 아래 순서는 제품 적합성에 대한 판단이며 유입·순위를 보장하지 않는다.

## 1. 먼저 전할 한 문장

한국어: **AI로 만든 프로젝트, 어떻게 연결되는지 직접 이해하세요.**

설명: 프로젝트 시각화·AI 사용량·방문 통계를 내 컴퓨터에서 확인하세요.

영어: **Understand how your AI-built projects fit together.**

설명: Explore project structure, AI usage, and visitor analytics from a local dashboard.

중심은 사용량 수집보다 ‘내가 만든 앱을 내가 이해하는 지도’다. 화면 → 서버 → DB가 어떤 역할을 하는지 쉬운 설명과 근거 파일을 보여 준다. 계정과 사용량은 그 이해를 돕는 정보로 소개한다.

- 형태: 제품 등록 후, 실제 예시 지도를 보여 주는 짧은 제작 이야기. 최종 게시 화면의 형식·현재 커뮤니티 규칙은 게시 전에 확인한다. 상세 게시 규칙과 글자 제한은 이번에 확정하지 못했다.

## 3. 한국어 · 디스콰이엇 짧은 글

AI로 앱은 만들었는데, 정작 화면·서버·DB가 어떻게 연결되는지 설명하기 어렵더라고요. 프로젝트마다 GitHub·Vercel·DB 계정도 달라 더 헷갈렸고요.

그래서 Manage-A를 만들었습니다. 프로젝트를 지도로 보고, 구성 요소를 누르면 쉬운 설명과 근거 파일을 확인하는 로컬 대시보드예요. AI 사용량과 방문 통계도 지원하는 연결 방식에 맞춰 모아 볼 수 있습니다.

무료·MIT 오픈소스이며 한글·영어를 지원합니다. 소개 페이지에서는 설치 없이 고정 예시 지도를 볼 수 있어요.

‘이 지도를 보면 내가 만든 앱을 설명할 수 있겠다’는 느낌이 드는지 궁금합니다. 특히 어디가 여전히 어려운지 알려주세요.

## 4. 한국어 · Show GN 초안

제목: Manage-A — AI로 만든 프로젝트의 연결 구조를 살펴보는 로컬 대시보드

바이브코딩으로 프로젝트는 늘어났는데, 화면·서버·DB의 연결과 프로젝트마다 다른 서비스 계정을 이해하고 관리하기 어려워 만들었습니다.

Manage-A는 내 컴퓨터의 프로젝트를 읽고 구조를 시각화하는 무료 MIT 오픈소스 도구입니다.

- 서비스 지도: 화면·서버·DB·배포의 역할과 근거 파일을 클릭해 확인
- 프로젝트별 서비스 계정 정리: 어떤 프로젝트가 어느 계정과 연결되는지 확인
- AI 사용량: 지원하는 연결 방식에 따라 구독 한도와 API 사용량을 구분
- 방문·검색: 권한이 있는 GA4·Search Console 속성을 연결해 조회
- 한글·영어 UI와 사용설명서

기본은 127.0.0.1 로컬 실행이고 Node.js 22.9 이상이 필요합니다. 외부 연동은 각 계정의 권한과 설정이 필요하며, 모든 서비스의 잔량을 자동으로 가져오는 것은 아닙니다. 지도는 코드에서 확인한 근거와 추정을 구분하고, 움직이는 점은 설명용이며 실제 트래픽 추적이 아닙니다.

GitHub의 실행 방법으로 사용해 볼 수 있습니다. 설치 전에는 소개 페이지의 고정 예시 지도도 볼 수 있어요.

구조를 처음 접하는 분에게 설명이 충분히 쉬운지, 설치 과정에서 어디가 막히는지 피드백을 받고 싶습니다.

## 5. 영어 · 일반 메이커 커뮤니티 초안

아래는 HN 제출용이 아니다. Reddit 등에서는 게시 직전 해당 공간의 규칙을 확인한다.

Title: I built a local dashboard to understand the projects I made with AI

I could build apps with AI, but explaining how their interface, server, database, and deployment connected was much harder. Different service accounts across projects made that even more confusing.

So I built Manage-A: a free, MIT-licensed local dashboard for understanding those projects.

You can explore a service map, click components for plain-language explanations and source-file evidence, and organize service accounts by project. It also supports AI usage and Google Analytics / Search Console integrations, with setup and permissions required for each connection. The interface and guides support English and Korean.

The app runs locally on 127.0.0.1 with Node.js 22.9+. The public website has a fixed example map you can explore before installing; it does not scan your projects. Animated connections explain the structure—they are not live traffic tracing. Usage collection depends on the provider and connection method, so some values require manual setup or recording.

I'm looking for feedback from people who build with AI but don't yet feel confident explaining their app's architecture. Which part of the map still feels confusing? If you try running it, where do you get stuck?

## 7. 게시에 함께 넣을 자료

- 첫 이미지: 개인정보 없는 예시 프로젝트의 ‘화면 → 서버 → DB’ 지도. 영어 채널은 영어 화면.
- 두 번째 이미지: 구성 요소를 선택했을 때 쉬운 설명·근거 파일이 나타나는 장면.
- 15~30초 영상 또는 GIF: 지도 선택 → 설명 확인 → 한/영 전환. 실제 계정·프로젝트명·경로·사용량은 공개 전에 제거하거나 합성 예시로 대체.
- 글당 요청 하나: 첫 글은 ‘지도 이해도’, 후속 글은 실제 개선 내용과 ‘설치가 되는지’. 같은 홍보글 반복 배포는 피한다.
- 실행 목표(자체 제안, 성과 아님): 첫 일주일에 지도 피드백 5건, 타인 로컬 실행 확인 3건. 홍보 효과를 별도 추적할 경우 개인정보 처리·통계 수집 방식부터 정한다. 이번 작업에서 새 추적 도구는 설치하지 않았다.

## 8. 공개 상태와 주의할 표현

- 무료는 Manage-A 코드·로컬 실행을 뜻한다. 외부 서비스의 무료 사용량·요금을 보장하지 않는다.
- ‘모든 계정 자동 연결’, ‘실시간 트래픽’, ‘완벽한 자동 아키텍처 분석’, ‘모든 AI 한도 자동 조회’라고 쓰지 않는다.
- 연결 가능과 실제 수신 완료를 구분한다. 제공자 원문·사용자 메모는 일부 원어로 남는다.
- MIT 라이선스와 앱 한·영 기능은 적용됐다. 이번 글은 게시하지 않은 초안이다.
- 검색 서비스 등록·소유 확인·사이트맵 제출·색인 미완료. 기술 SEO와 검색 등록을 혼동하지 않는다.
